## ✍️ Description

Add reposilite, a Maven repository manager, as an unprivileged Alpine LXC
application running directly on Java 21 with OpenRC. Defaults are Alpine 3.24,
1 CPU, 1024 MiB RAM, 8 GiB disk and HTTP port 8080.

The Core wizard accepts repository names/visibility, quota, redeployment policy,
heap, data directory, manager name and dashboard text. Optional native profiles
configure MariaDB/MySQL/PostgreSQL, S3-compatible artifact storage, mounted
filesystem storage, LDAP/LDAPS and HTTPS with provided or self-signed PEM files.
Passwords use hidden TTY entry or a private host-side JSON file. No reverse
proxy, OIDC gateway, Docker runtime or ACME service is installed.

A persistent manager token replaces the temporary startup token. Private files
use restrictive permissions, LDAP excludes the initial local manager, and
repository mounts/namespaces are checked for overlap. An external database must
be dedicated and empty; tables, views and partitioned relations are refused
before application initialization.

Updates use Core release discovery and the publisher's Maven SHA256, retain
configuration/data, back up application and local state after a clean stop, and
authenticate a listing of each repository. Replacement/start/readiness failure
restores the previous application and leaves it stopped for database review.
The live database is never automatically rolled back across a possible migration.
New installs retain a headless Java 21 runtime after the one-time JDBC preflight,
and remove only known setup files after authenticated repository readiness.
A persistent recovery marker also blocks OpenRC startup after an interrupted
update or reboot until an administrator reviews the JAR/database state.

Unattended updates use the Core-generated update entrypoint and PHS_SILENT.
For standalone distribution, a separate SHA256-pinned update-apps adapter routes
only reposilite/legacy metadata lookups here; other applications retain the
official source root. Official update-lxcs handles Alpine packages separately.
A disabled-by-default cron template and operator instructions are included.
The unmodified official update-apps tool does not discover this standalone app.

Proposed application files:
- ct/reposilite.sh
- install/reposilite-install.sh
- json/reposilite.json
- misc/reposilite-config.py
- misc/DatabasePreflight.java
- misc/reposilite-update-guard.sh

The legacy standalone ct/alpine-reposilite.sh redirect is not proposed as a new
upstream application. The standalone host adapter and cron template are not
proposed as application files. Standalone CI/tests/docs should be packaged separately
from the application files according to maintainer guidance.

## 📋 Additional Information

Review decisions still needed:
- Keep the requested reposilite slug or agree on the upstream alpine- convention.
- Change _CS_DEFAULT_URL to DevScripts in a future upstream branch. It currently
  points to the standalone repository intentionally; official ct-base fails as-is.
- Agree on packaging the configuration, JDBC preflight and OpenRC guard helpers.
- Review the separate standalone update-apps adapter. Once this application is
  accepted upstream, the official catalog lookup should replace that adapter.
- Review the Maven JAR exception: GitHub releases have no binary assets, and the
  generic URL deployment helper does not preserve the executable JAR as required.
  Current code preserves the executable JAR and verifies its official Maven checksum.
- Native self-signed TLS uses Python/OpenSSL because the actual Alpine helper
  does not expose create_self_signed_cert. No nginx workaround is proposed.
- Complete current Proxmox installation, native integrations, reboot, update and
  failure-recovery validation, then have the author review these declarations.

Upstream 3.6.5 Dockerfile, docker-compose.yml and .env were inspected. They use
Java 21, port 8080, a persistent data volume and Java/application options. This
integration installs the published executable JAR instead of building the image.
MySQL/PostgreSQL retain upstream's experimental status. No OIDC setting exists
in the verified native configuration. Mounted NFS/SMB needs host/LXC provisioning.
