Runtime contracts

PASS  Current local-first core/build.func bootstrap; script and Core roots can
      be overridden independently. No host commands or custom telemetry/traps.
PASS  CT defaults and exported app_vars agree with json/reposilite.json.
      Inputs are honoured before prompting; secret JSON fields are marked.
PASS  Core prepared FUNCTIONS_FILE_PATH reaches the Alpine installer.
PASS  setup_alpine/run_os_setup and update_alpine/run_os_update cover the one
      supported OS family. OpenRC is used; no systemctl or containerized app.
PASS  JAVA_VERSION=21 setup_java supplies the temporary full JDK for JDBC
      preflight. The installer then explicitly retains openjdk21-jre-headless
      before removing the JDK/compiler/GUI dependencies. Native config uses only
      Python's standard library, without pip/venv/application Python runtimes.
PASS  start() loads tools.func on update, then the general Forge release helper.
      The updater now distinguishes no-update 1 from errors such as 6/22/250.
PASS  CT helper fetching now uses curl_with_retry with the script-source root.
      A regression test checks remote-root selection and temporary-file cleanup.
PASS  Standard lifecycle/messaging, existence checks, update exit, downloads,
      backups and final motd_ssh/customize/cleanup_lxc calls are present.
PASS  Shell syntax plus additional ShellCheck/shfmt gates, metadata/input checks
      and the automated suite in TESTING.txt. JDBC checks use the official JAR.

Unattended update tool contracts

PASS  Actual Core write_update_entrypoint and misc/update.sh preserve the stored
      standalone root and PHS_SILENT=1. Website state=unknown permits updates;
      legacy slug resolution, helper fallback and error status are exercised.
GAP   Unmodified official update-apps only looks in the official app repository;
      it skips this standalone app, even with an explicit CTID. Metadata alone
      cannot fix that. Use the explicit tools/pve/update-apps.sh adapter.
PASS  The adapter verifies a pinned source hash/context and changes only two URL
      lookups. Both Reposilite slugs use canonical metadata here; other apps
      retain official lookups. Original unattended, backup and OS paths remain.
PASS  Official update-lxcs executes apk -U upgrade in Alpine. That updates OS
      packages, including Java, and does not replace the Reposilite JAR.
PASS  Persistent OpenRC recovery protection survives failed/killed updates and
      reboot. Authorization requires the live updater and its exclusive lock.
      Core retains ownership of the update entrypoint and signal/error traps.
NOTE  Cron templates are supplied but no host job is installed. Upstream dry-run
      can start stopped containers/repair a legacy entrypoint. See AUTO-UPDATES.txt.
PASS  The adapter also ran on real PVE 9.1.1/amd64 for one explicit CT in
      unattended mode. Its already-current application path completed; no other
      CT was selected and no app-update cron was installed. Full-LXC backup,
      multi-CT batch recovery and scheduled execution remain unverified.

Generator and architecture

PASS  The deployed generator honours the explicit install_methods[].script and
      recognises resources.os=Alpine with method type=default. It can therefore
      identify ct/reposilite.sh without changing the requested standalone slug.
NOTE  The official generator chooses official application repositories. Adding
      JSON here does not register this app in the official website's catalogue.
PASS  var_arm64 is unset and architectures is omitted, matching the documented
      unverified state. ARM64 is not claimed supported; metadata lists PVE only.
PASS  Fresh Alpine 3.24.3/amd64 PVE deployment with external PostgreSQL, RustFS
      S3 and native HTTPS passed, followed by a verified same-version update and
      reboot. Incus/ARM64 and cross-version migrations remain unverified.

Intentional standalone differences / future upstream changes

FAIL  Official ct-base requires a DevScripts _CS_DEFAULT_URL in every CT file.
      Current primary CT points to this standalone repo; the old-slug file is a
      redirect. Keep them functional here. For a future upstream branch, change
      the primary source root and omit the historical standalone redirect.
GAP   Alpine-only upstream naming normally uses alpine-. The requested reposilite
      slug is retained and needs maintainer agreement before submission.
GAP   Review placement/maintenance of misc/reposilite-config.py and the Java
      preflight/guard, plus which standalone tests/docs belong in an upstream patch.
      The host adapter is standalone tooling and is not part of the app proposal.
EXC   Reposilite publishes its executable JAR through Maven, not GitHub assets.
      Core discovers releases and supplies download helpers; the original JAR
      and its SHA256 are preserved. The generic URL deployment helper does not
      preserve the executable JAR as required.
EXC   Guidance prefers create_self_signed_cert. The generic system helper has
      hostname/SAN support, but the actual Alpine installer helper does not
      expose it. Native Python/OpenSSL TLS is retained without a reverse proxy.
NOTE  ShellCheck/shfmt are extra standalone checks, not a claim that upstream
      CI requires identical tooling. Its Bash syntax/layout contracts were read.

Evidence and limits

- Current Core DNS-failure status 6 was reproduced; updater tests exercise
  1/6/22/250 with a running service and verify only 1 becomes success.
- Native 3.6.5 filesystem overlap leakage was reproduced before the fix. After
  rejection/isolated-mount changes, private upload stayed private (401) and the
  corresponding public artifact path returned 404. Symlink aliases were tested.
- Current JDBC preflight rejects PostgreSQL regular/partitioned tables, views
  and materialized views without changing objects/data; an empty database still
  passes. MariaDB empty/existing-table regression checks passed too.
  Quoted uppercase user schemas cannot impersonate excluded system schemas.
- Actual supported quota formats registered native providers. B/TB suffixes and
  signed-long overflow are rejected before container creation.
- Earlier PVE and Docker/OpenRC fixture results remain historical. The new
  PVE 9.1.1 deployment/update/reboot evidence has its own scope in TESTING.txt.
- Existing dashboard settings are preserved. The installer cannot guarantee
  isolation after manual edits or detect every alias of mounted/remote storage.
